# Source and release review — 10 September 2026

This review compared the replacement firmware, embedded setup page and release
instructions with the captured protocol, previous hardware observations and
the installed ESP8266 Arduino core **3.1.2**. Source changes below were
subsequently compiled, flashed and validated as v1.0.0 on
11 September 2026. See [Testing status](TESTING.md) for the current state.

## Firmware changes

| Finding | Change |
| --- | --- |
| Fallback passed a temporary `String::c_str()` to SNTP, which retains the pointer. Once the temporary expired, the hostname could become invalid. | Use the core's `String` overload of `configTime`, which keeps its own server-name copy. |
| A station connection arriving after the 20-second deadline was ignored in portal state. | A late successful connection now starts NTP. |
| The sketch abandoned SNTP completion after its timeout although the core continued retrying. | Preserve the eight-second fallback policy, then continue accepting a late valid reply for this wake. |
| A synchronous Wi-Fi scan suspended the main loop, delaying MM32 handshakes and ticks; starting it during association could disconnect the station. | Start/poll scans asynchronously, deferring them until the connection attempt finishes. |
| Save and reboot were separate browser requests, allowing saved settings to remain unapplied if the second request was lost. | One POST commits settings, returns a result and schedules restart. Pending restart suppresses time announcements. |
| Blank password reused credentials from a different SSID. | Preserve only when the SSID is unchanged; a new SSID starts with the entered password, including blank for an open network. |
| Runtime configuration changed before an EEPROM commit could fail. | Commit a candidate first, then assign the running configuration. This does not make a single-sector EEPROM write immune to power loss. |
| Numeric parsing accepted malformed/missing values as zero, and stored strings lacked termination checks. | Parse whole numeric fields and validate fixed-size strings before loading them. Preserve the existing storage layout. |
| JSON escaping did not cover all control bytes. | Escape control bytes, quotation marks and backslashes so unusual scan results cannot break the JSON response. |

The public core documents [asynchronous scanning](https://arduino-esp8266.readthedocs.io/en/3.1.2/esp8266wifi/scan-class.html).
Its [Arduino.h declarations](https://github.com/esp8266/Arduino/blob/3.1.2/cores/esp8266/Arduino.h)
and [time.cpp implementation](https://github.com/esp8266/Arduino/blob/3.1.2/cores/esp8266/time.cpp)
explain the server-name lifetime requirement and `String` overload used here.

## Setup-page changes

The established layout, labels and controls are retained. The script is now
formatted for maintenance, deduplicates scanned SSIDs by their strongest signal,
keeps manual entry last, and updates the password hint for the selected SSID.
Blank default NTP/time-zone fields display their defaults as placeholders.

Requests have a six-second timeout. Status and heartbeat polling do not overlap
their own pending requests, do not overwrite form edits, and stop after a
successful save/reset. Page closure stops polling and tries a close notification;
a failed beacon queue falls back to fetch. The firmware's 10-second
expiry remains necessary when the browser cannot deliver that notification.

Save remains one button: commit settings, schedule ESP restart, reconnect to the
saved network, obtain NTP time with fallback, then send `+TIME`. Success on the
page confirms saving, not a successful NTP response or physical hand movement.

## Protocol and timing

- `USER\n` replies immediately with `USER_OK\r\n` at 115200 baud, including
  before NTP succeeds, without diagnostic UART logging.
- A valid SNTP reply precedes `+TIME`. The first record now follows after about
  one second; when a page session is active, `+TICK\r\n` is sent first and the
  first time record follows about one second later. This supersedes the
  replacement firmware's earlier unconditional five-second grace period.
- `+TIME` repeats once per second, with local date/time, UTC offset and `HH:MM`.
- Page-session `+TICK` and connection-status polling retain their two-second
  cadence; the firmware uses a one-minute session cap.
- The first captured `CLEAN\n` arms physical reset and a repeat 1–4 seconds
  later confirms it. The firmware then clears replacement settings and residual
  SDK station credentials, replies `CLEAN_OK\r\n` after a successful commit,
  and restarts once. With blank settings, later commands are acknowledged but
  cause no flash write or restart. This behaviour was later validated on
  v1.0.0.
- No wake-cause guess, OTA handler or MM32 firmware change.

## Documentation corrections

The flashing guide now distinguishes NodeMCU printed RX/TX labels from a
dedicated USB-UART adapter's directions. It explains both reset holds, clock
power, the required reset edge with GPIO0 low, normal boot afterward, two-read
backup verification and restoration of the personal original image. The early
harness photo is identified as historical; it predates the successful RX/TX
correction.

Build instructions now name the tested **Generic ESP8285 Module** and core
3.1.2. `FLASH_MAP_NO_FS` removes the filesystem; it does not itself prohibit OTA.
OTA remains omitted because an uninterrupted update and recovery procedure has
not been established for this movement. The precise external reset/enable/power
circuit is still unmapped and is no longer described as fully proven.

## Initial review validation and remaining work

This section records the initial review. Subsequent preparation added supported
POSIX syntax validation, request guards, session ownership and further browser
checks. The current v1.0.0 state supersedes its open items; see
[Testing status](TESTING.md).

The initial fourteen dependency-free Node.js checks were expanded to 21. They
execute the actual page script with a
simulated DOM and HTTP responses; they also check that `web_ui.h` matches the
HTML. See [Testing status](TESTING.md) for coverage and hardware tests.

The following were the initial open items. They are retained as review context;
hardware validation and v1.0.0 publication closed them:

- **Daily wake:** a known `22:00` stock control wake succeeded. Although stock
  stored and transmitted arbitrary `HH:MM` values, the MM32 did not reliably
  honour them. Current source consequently restricts the setting to `09:00`,
  `10:00`, `21:00`, or `22:00`; the replacement behaviour was later validated.
- **Time-zone validation:** the initial review had only length/control-byte
  checks. Subsequent source now validates a supported POSIX subset, and
  real-device integration was later validated.
  The library applies valid DST rules when ESP time is converted; behaviour
  between updates depends on the MM32. Do not promise a DST transition before
  the next successful synchronization.
- **Configuration access:** the AP is open, HTTP is unencrypted, and configuration
  and Factory reset endpoints have no authentication. Anyone with network access
  during a wake can change settings. This is now documented as an intentional
  trusted-local-network boundary in [SECURITY.md](SECURITY.md).
- **Reset semantics:** both the page and the captured physical `CLEAN` path erase
  this firmware's EEPROM configuration and residual SDK station credentials.
  They do not erase every flash byte or anything held by the MM32.
- **Release reproducibility:** the v1.0.0 application export, paired clean
  1 MiB recovery image and `SHA256SUMS.txt` are published on the
  [v1.0.0 GitHub Release](https://github.com/maddenste/Chouchin-CH899-Firmware/releases/tag/v1.0.0).
  No vendor binary or private capture is published.

The previous firmware source, HTML and embedded header were retained in the
ignored local `private/review-2026-09-10/` folder for comparison. Existing
earlier images remain unchanged.
